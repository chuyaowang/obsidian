## Introduction to Learning with Graphs

Graphs are fundamental structures that model relationships between entities. They are prevalent in various real-world applications, including social networks, knowledge representation, and recommendation systems. Understanding how to learn from graphs is crucial for tasks such as node classification, link prediction, and clustering.

### Undirected graph

- Simple graph
	- Made of two parts: connected parts and unconnected parts
	- The graph is called a **connected graph** when all nodes are connected
- Self loop
	- A node connects to itself
	- For example, in a molecule, two same atoms can have a bond between them
- Multigraph
	- Multiple edges between nodes
	- For example, each edge represents a meeting that happened between two people (the nodes)

### Directed graph

- Edges can have directions, and directions can have meanings.
- For example, one person follows another person on a social network. In this case a reciprocal edge can also be drawn between them.
- Directed and undirected edges can co-exist in a graph.

### Labels and types

- Edges and nodes can be labeled.
	- For example, Bob (node) likes (edge) cheese (node)
- Node can be labeled with types.
	- For example, Bob has a type (person). Cheese has a type (food).

### Resource description framework

- RDF is a type of graph that uses edge and node labels/types
- Each node is *labeled* with a URL or a literal value, like a number
- All edges are directed. Each edge can also be *labeled* with a URL
- This approach makes the nodes and edges unique. The network is more expressive.

### Information on edges

- Label edge with weights: interpretation depends on how you analyze the graph.
	- For example: Bob (node) likes (edge) cream (node) with a score of 0.5 (weight) and likes (edge) cheese (node) with a score of 0.9 (weight)
- Properties labeled on edges: the additional details are known as qualifiers
	- For example, Bob likes cream, but with added temporal and contextual details. For instance, he prefers this cream only in the evenings and exclusively with coffee.

## Embeddings

- Embeddings: low-dimensional representations of objects. 
- Low dimension, in the context of embeddings, means a representation much smaller than the original size.
- Embeddings can be created for words, sentences, images, audio, and even graphs.

### Image embeddings

- Images passing through convolutional layers resulting in a smaller dimension input is an example of embedding.
- VAEs generate points in a distribution space that serve as embeddings for the real world image.
- Some embedded spaces exhibit a valuable structure that allows navigation. Moving in specific directions within this space holds meaningful changes in certain features of the object. 
	- For example, in images, navigating could transition from a smiling person to a non-smiling one or from a female to a male gender along a certain direction.
	- This way, the different semantic features of the object (gender, mood) are disentangled in the embedding space.

### Word embeddings

- **Distributional hypothesis**: understanding a word involves its contextual associations.
	- For instance, words like 'cat,' 'dog,' and 'fish' frequently co-occur with 'animal' but rarely with 'loudspeaker.' This implies that 'cat,' 'dog,' and 'fish' are semantically similar, while 'loudspeaker' is distinct. Leveraging such contextual information allows us to create embeddings for words.
- To create word embeddings, we use vector representations for each word and explore their co-occurence with other words.
- We can navigate word embeddings as well. For example, starting with the concept 'king,' navigating in a certain direction in space could lead to the word 'man.' This approach can extend to relationships like capitals to countries or transforming grammatical forms of words.

## Graph Embeddings

### Why use graphs for machine learning?

- Primary goals: classification, regression, or clustering of nodes, edges, or the entire graph. 
	- For instance, in an Amazon product graph with missing labels, we might want to _classify_ nodes, such as determining whether a product is poisonous or not. 
	- Regression could _quantify_ toxicity levels. 
	- Other applications include recommender systems for _product suggestions_ based on connections in the knowledge graph, document modeling to _find similar documents_ through graph links, and aligning graphs to identify _similarities between nodes_. 
	- Additionally, tasks like _link prediction_ and _error detection_ aim to refine and correct the knowledge graph by predicting missing links and rectifying inaccuracies.

### Graph Embedding Techniques

- With text or images, the structure is either 1 or 2 dimensional, which can be easily fed into a neural network
- Graphs can't be neatly represented in a linear fashion. Therefore, feeding them into our network becomes a non-trivial task.
- Traditional machine learning on graphs: uses **manual feature engineering**. The features are then used for the machine learning algorithm. This approach suffers from scalability issues and task specific. Not discussed in this lecture.
- Instead, we focus on **embedding knowledge graphs in a vector space**. More precisely, we'll discuss **embedding nodes in an effective space**. The approach involves taking each node in the graph and creating a vector in a vector space for each node. These vectors are designed to be easily integrated into a machine learning algorithm.

#### Node embeddings

- What we do is akin to something called **propositionalization**. This involves creating one vector for each entity or node in the graph. Then the vectors can be used for data mining or machine learning algorithms.
- We want the embedding method to preserve information from the original graph and ideally unsupervised. So the embeddings obtained are task and dataset independent. They originate from a specific graph but should be universally applicable.
- Efficacy is crucial. Some networks can have millions of nodes and connections. The embedding should be *low dimensional* and *compact* to save space.

#### Two visions on node embedding

- There are two visions of how node embeddings should be done:
	- Preserving **topology**: neighbors in the graph are neighbors in the embedding. For example, if Germany and France are neighbors in a graph, they should be close in the embedding space.
	- Preserving **similarity**: similar nodes have similar embeddings. For example, you might have separate embeddings for Europe and Africa, and because they are both continents, they would be close together in the embedded space. Likewise, Germany and Algeria, both being large countries, would also have close embeddings in the same space.

#### Two major targets

- There are two major targets when creating node embeddings, related to the [tasks discussed](#Why%20use%20graphs%20for%20machine%20learning?)
- Improving the original data: related to the graph itself
	- knowledge graph completion
	- link prediction
	- anomaly detection
- For downstream ML tasks:
	- Classification, regression, or clustering
	- Become part of a larger process
		- QA/dialog system
		- Translation
		- Image segmentation: if entity is a cow, background is more likely to be farm rather than sea

> How do we create graph embeddings?

### Three approaches of graph embedding

- **Translational**: any relation existing in the knowledge graph is directly mapped to its counterpart in the embedded space.
- **Tensor factorization**:  involves creating a 3D matrix of all the relations in the graph. Then factorize the matrix. Reconstructing the original hints which edges were _missing_. 
- **Random walk based**: the process includes starting at a particular node and navigating its _context_ for embedding. This method incorporates the distributional hypothesis  (i.e. for words, its context encodes its meaning).

### Translational Embedding

- TransE
- In large knowledge graphs
	- There are nodes
	- The nodes are connected by typed edges
- Generate embedding for nodes connected by typed edge. Then generate embeddings for the typed edges so they serve as translation from the head node to the tail node that the edge connect to.
- When an edge is used repeatedly, the same edge embedding is used.
- Optimization goal: align the head ('h') of the relationship, the edge, and the tail
	- head+edge should $\approxeq$ tail as much as possible
	- it should also penalize instances where incorrect triples or relations in the graph are in close proximity
		- a triple: head, translation, tail
		- valid triple: (Paris, IsCapitalOf, France)
		- invalid triple: (Paris, IsCapitalOf, America)
- Done by taking head or tail of the triple and swapping it for something else random to create false triples.
- Loss function: $$\mathcal{L} = \sum_{(h, r, t) \in \mathcal{T}} \max(0, \gamma + \|\mathbf{h} + \mathbf{r} - \mathbf{t}\| - \|\mathbf{h}' + \mathbf{r} - \mathbf{t}'\|)$$
    - Explanation of Terms:
        - $\mathcal{T}$: Set of all training triples.
        - $\mathbf{h}, \mathbf{r}, \mathbf{t}$: Embeddings of the head, relation, and tail for a valid triple.
        - $\mathbf{h}', \mathbf{r}, \mathbf{t}'$: Embeddings for an invalid triple, often created by corrupting the head or tail.
        - $\gamma$: Margin that separates valid and invalid triples.
    - How It Works:
        - The loss enforces:
            - Valid triples ($\mathbf{h}, \mathbf{r}, \mathbf{t}$) to have small distance $\|\mathbf{h} + \mathbf{r} - \mathbf{t}\|$.
            - Invalid triples ($\mathbf{h}', \mathbf{r}, \mathbf{t}'$) to have large distance $\|\mathbf{h}' + \mathbf{r} - \mathbf{t}'\|$.
        - The loss penalizes the model when: $\|\mathbf{h} + \mathbf{r} - \mathbf{t}\| + \gamma > \|\mathbf{h}' + \mathbf{r} - \mathbf{t}'\|$
        - This means:
            - If the distance for the valid triple $\mathbf{h} + \mathbf{r} - \mathbf{t}$ is **not sufficiently smaller** than the distance for the invalid triple $\mathbf{h}' + \mathbf{r} - \mathbf{t}$, the loss becomes positive.
            - The model is then updated to decrease the valid triple distance and/or increase the invalid triple distance to satisfy the margin constraint.
- Advantage: conceptually easy
- Disadvantage: 
	- poor embedding quality
	- the better the model, the less scalable it is
	- only considers information from one-hop neighbors

### Tensor factorization

- Tensor example: for a 3D tensor $X$
	- $i$: entities
	- $j$: entities
	- $k$: whether relation exists (1 or 0)
- Factorize the tensor to obtain the embeddings
	- For RESCAL, the tensor is factorized into 3 components. Two for entity embeddings and one for relations.
	- When the large sparse tensor $X$ is decomposed, it becomes smaller matrices. Entities with similar neighborhoods get similar embeddings.
	- In the process, noise, anomalies, and mistakes in the graph are discarded.
	- Reconstructing the matrix from the components gives something close to the original graph. Missing edges not in the original graph are predicted.
	- Other applications include: cluster entities, measure similarity, feed embeddings into downstream models, and visualize the latent structure of the graph
- Advantage:
	- Conceptually easy
	- Effective for link prediction
	- Usually scalable
	- Encodes multi-hop information
- Neutral:
	- Explainable
	- Numeric attributes can be incorporated somehow
- Disadvantage:
	- Embedding quality for downstream ML task
	- Scalability decreases with increased network complexity

### Random walk based

#### RDF2Vec and node2vec

- Randomly walk around a node, generate a sequence of nodes, edges, and their labels
- Feed the sequence to word2vec to generate embeddings
	- Example sequence: This person likes milk. Milk is similar to cheese, and cheese contains a high amount of fat.
- The word embeddings correspond to concepts in the graph
- Generates an embedding for the graph
- Weighting can be used to bias some directions during the walk
- Graph kernels can be used to navigate the graph

#### Personalized PageRank

Personalized PageRank–based graph embeddings treat the graph the same way distributional semantics treats language: **a node’s meaning is defined by the company it keeps**. The method is essentially a two‑stage pipeline:

1. **Use personalized PageRank (PPR) to compute a rich, global notion of context for every node.**  
2. **Feed those contexts into a language‑model‑style embedding method such as GloVe.**

This produces embeddings that behave analogously to word embeddings, including analogy‑preserving structure, but grounded in graph topology instead of text.

---

##### How personalized PageRank creates node contexts

Personalized PageRank starts a random walk from a specific node and repeatedly “teleports” back to that node with some probability. The result is a **probability distribution over all other nodes**, weighted by how reachable and important they are relative to the starting point.

For each node \(u\), PPR gives you a vector:

- High weights for close neighbors  
- Medium weights for nodes reachable through multiple paths  
- Low or zero weights for distant or disconnected nodes  

This captures **both local and global structure**, unlike simple adjacency or short random walks.

These PPR vectors act like **co‑occurrence statistics** in language modeling:  
nodes that frequently appear in each other’s PPR neighborhoods are treated as semantically related.

---

##### Why GloVe is used on top of PPR

GloVe is built to learn embeddings from **global co‑occurrence matrices**. It optimizes embeddings so that:

- Dot products reflect co‑occurrence ratios  
- Linear relationships encode analogies  
- Rare but meaningful co‑occurrences are preserved  

When you feed PPR‑based co‑occurrence data into GloVe, you get:

- **Node embeddings** that reflect structural similarity  
- **Analogy‑like relationships** (e.g., “Paris – France + Italy ≈ Rome”)  
- **Smooth generalization** across the graph  

This is more systematic than random‑walk‑based methods like DeepWalk or node2vec, which rely on sampling and may miss important parts of the graph.

---

##### How this differs from random‑walk embeddings

Random‑walk methods approximate context by sampling sequences of nodes. Personalized PageRank + GloVe instead:

- Computes **complete** context distributions  
- Avoids sampling noise  
- Captures long‑range dependencies more reliably  
- Preserves global structure in a single optimization step  

The result is often more stable and more interpretable embeddings.

---

##### Why this works: the distributional hypothesis for graphs

The same principle that underlies word embeddings applies:

> Nodes that appear in similar graph contexts should have similar embeddings.

Context here means not just immediate neighbors but the entire PPR‑weighted neighborhood. This allows the model to capture:

- Structural roles (hubs, bridges, leaves)  
- Community membership  
- Functional similarity  
- Multi‑hop relationships  

It also enables **link prediction**, because nodes with similar PPR profiles tend to form similar edges.

---

##### Where this method shines

- Graphs with strong community structure  
- Knowledge graphs where long‑range relationships matter  
- Networks where random walks are too noisy or biased  
- Tasks requiring analogy‑like reasoning or role similarity  

It’s especially useful when you want embeddings that reflect **global graph geometry**, not just local adjacency.

##### Evaluation

- Advantage:
	- deals with large graphs
	- good embeddings
	- good training time
- Neutral:
	- likely or partially explainable
	- larger context used
- Disadvantage: 
	- link prediction: these methods prioritize semantic similarity based on the distributional hypothesis, potentially overlooking the original graph's structure
- Some examples:
	- **Node2Vec**: Employs biased random walks to capture network neighborhoods, generating node embeddings that reflect community structures.
	- **DeepWalk**: Utilizes truncated random walks to learn latent representations by treating walks as sentences in a language model.
	- **LINE**: Preserves both first-order (local) and second-order (global) proximities in the network, ensuring embeddings capture both immediate and broader network structures.

## Graph neural networks

- Creating embeddings first then use it for ML tasks is not end-to-end learning
	- certain information deemed unimportant during the embedding process might be discarded, potentially impacting the application.
- With end-to-end learning, a different challenge arises. The embeddings generated in such a system may lack generalizability, being too specific to the task at hand. Unlike the two-step approach, they may not be transferable to other tasks.

### Graph convolutional neural network

- We can convert a graph to a multilayer network, with each layer repeating the connections in the original network
- Also add self-loops in the network, represented as connection between a node to itself in the next layer
- Each connection is a small MLP. The input is a node, which is a n-dimensional vector, the output is also a vector. 
- The weight is shared for all connections in this layer and can be learned.
	- resembles how filters are shared in CNN, hence the name GCNN
- In practice, it scales not exceptionally well to large graphs
	- with clever engineering, scalability can be improved. ex. PyTorch Geometric library
- Another issue is the need for increased normalization:
	- some nodes are more connected; when information is aggregated through layers, these nodes have higher feature values
	- this causes learning to bias towards the more connected nodes
	- normalization resolves this issue

#### Compact representation of GCN:

$H^{(l+1)} = \sigma(\tilde{D}^{-1/2} \tilde{A} \tilde{D}^{-1/2} H^{(l)} W^{(l)})$

- $H^{(l)}$: Node features at layer $l$.
- $\tilde{A}$ = A + I: Adjacency matrix with added self-loops.
- $\tilde{D}$: Degree matrix of $\tilde{A}$, where $\tilde{D}_{ii} = \sum_j \tilde{A}_{ij}$.
- $\tilde{D}^{-1/2} \tilde{A} \tilde{D}^{-1/2}$: Normalized adjacency matrix.
- $W^{(l)}$: Trainable weight matrix.
- $\sigma$: Activation function.

Instead of looking at the network node-by-node using Multi-Layer Perceptrons (MLPs), this approach computes the state of *all nodes in the graph simultaneously* using sparse matrix multiplication.

Here is a breakdown of how this formulation works and what each component represents.

##### The Core GCN Formulation

The update rule for a single GCN layer is defined by the following equation:

$$H^{(l+1)} = \sigma\left(\tilde{D}^{-\frac{1}{2}} \tilde{A} \tilde{D}^{-\frac{1}{2}} H^{(l)} W^{(l)}\right)$$

##### Breakdown of the Variables

* **$H^{(l)}$ and $H^{(l+1)}$ (Node Features):** * $H^{(l)}$ represents the state (or feature matrix) of all nodes at layer $l$.
* $H^{(l+1)}$ is the updated state for the next layer. By multiplying the matrices, the network processes the entire graph structure at once rather than looping through individual nodes.
* **$W^{(l)}$ (Learnable Weights):** * This is the weight matrix for layer $l$. As the speaker notes, this matrix is "applied universally" and "shared across all nodes." It transforms the input features into a new feature space before they are passed to neighboring nodes.
* **$\tilde{A}$ (Adjacency Matrix with Self-Loops):** * $A$ is the standard adjacency matrix representing connections (1 if a connection exists, 0 otherwise).
* $\tilde{A}$ is the adjacency matrix with the diagonal set to 1. This adds a "self-loop" to every node, ensuring that when a node aggregates information from its neighbors, it also includes its own previous state.
* **$\tilde{D}$ (Degree Matrix):** * Defined as $\tilde{D}_{ii} = \sum_j \tilde{A}_{ij}$, this is a diagonal matrix where each entry represents the number of connections (the degree) a node has, *including* its self-loop.
* **$\tilde{D}^{-\frac{1}{2}} \dots \tilde{D}^{-\frac{1}{2}}$ (Symmetric Normalization):** * This is the "specific technique" the speaker mentions to "scale and counteract the impact of having numerous neighbors."
* If you only multiplied by $\tilde{A}$, nodes with many connections would aggregate massive sums of feature values, while isolated nodes would have very small values. This normalization step divides the incoming messages by a factor derived from the degrees of both the sending and receiving nodes. This prevents the "undesired inflation of node values" and stabilizes the training process.
* **$\sigma$ (Activation Function):** * A non-linear activation function (like ReLU) applied element-wise to the resulting matrix to introduce non-linearity into the model.

##### Summary of the Operation

In simple terms, reading the equation from right to left inside the parentheses:

1. **$H^{(l)} W^{(l)}$:** Transform the current node features using learned weights.
2. **$\tilde{A} (\dots)$:** Pass these transformed features along the edges of the graph to neighboring nodes (including passing them to the node itself via self-loops).
3. **$\tilde{D}^{-\frac{1}{2}} (\dots) \tilde{D}^{-\frac{1}{2}}$:** Normalize these passing messages so high-degree nodes don't explode in value.
4. **$\sigma(\dots)$:** Apply a non-linear activation to get the final state for the next layer.

> [!info]- What is the -1/2 exponent
> In mathematics, an exponent of $-1/2$ combines two operations: a reciprocal and a square root.
> 
> For any number $x$, the rule is:
> 
> $$x^{-\frac{1}{2}} = \frac{1}{\sqrt{x}}$$
> 
> Here is exactly what that means in the context of the Degree Matrix ($\tilde{D}$) from the GCN formula.
> 
> ### 1. Applying it to the Degree Matrix
> 
> Because $\tilde{D}$ is a **diagonal matrix** (all entries are 0 except for the values along the main diagonal, which represent the degree of each node), taking the matrix to the power of $-1/2$ is very straightforward. You simply apply the $x^{-1/2}$ rule to each number on that diagonal.
> 
> If node $i$ has a degree of $4$ (meaning it has 3 neighbors plus 1 self-loop), its entry in the $\tilde{D}$ matrix is $4$.
> 
> In the $\tilde{D}^{-\frac{1}{2}}$ matrix, that entry becomes:
> 
> $$4^{-\frac{1}{2}} = \frac{1}{\sqrt{4}} = \frac{1}{2} = 0.5$$
> 
> ### 2. Why use -1/2 on both sides? (Symmetric Normalization)
> 
> In the formula, the adjacency matrix $\tilde{A}$ is sandwiched between two of these $-1/2$ powered matrices: $\tilde{D}^{-\frac{1}{2}} \tilde{A} \tilde{D}^{-\frac{1}{2}}$.
> 
> This creates a specific type of scaling called **symmetric normalization**. When you multiply these three matrices together, the message sent from node $j$ to node $i$ gets scaled by the following factor:
> 
> $$\frac{1}{\sqrt{\text{degree of node } i} \times \sqrt{\text{degree of node } j}}$$
> 
> This is a brilliant design choice for graph networks because it normalizes the message based on **both the sender and the receiver**:
> 
> - **The Receiver's perspective:** If node $i$ has 1,000 neighbors, it will receive 1,000 messages. Dividing by $\sqrt{\text{degree of } i}$ helps shrink those incoming messages so node $i$'s total value doesn't explode.
>     
> - **The Sender's perspective:** If node $j$ has 1,000 neighbors, its attention is highly divided. Dividing by $\sqrt{\text{degree of } j}$ means node $j$ sends a very weak signal to its neighbors. Conversely, if node $j$ only has 1 neighbor, it passes a much stronger, more concentrated signal to that specific neighbor.
>     
> 
> By using $-1/2$ twice instead of $-1$ once, the GCN respects the structural importance of both nodes involved in the connection.

### RGCN
#### Typed edges

- one weight matrix for each edge type
- reversed edge:
	- sometimes the default direction does not align with application
	- reverse edge: 'I live in Amsterdam' and 'Amsterdam has inhabited me'

#### Formulation

The core idea is to extend the GCN aggregation mechanism to account for multiple edge types (relations). The node embeddings at layer $l+1$ are computed as:

$$\mathbf{h}_v^{(l+1)} = \sigma \left( \sum_{r \in R} \sum_{u \in \mathcal{N}_r(v)} \frac{1}{c_{v, r}} W_r^{(l)} \mathbf{h}_u^{(l)} + W_0^{(l)} \mathbf{h}_v^{(l)} \right)$$
- Explanation of Terms:

1. $\mathcal{N}_r(v)**$:
    
    - The set of neighbors of node v that are connected via relation r.
2. **Relation-Specific Transformations ($W_r^{(l)}$)**:
    
    - Each relation $r \in R$ has its own weight matrix $W_r^{(l)}$ at layer $l$.
    - This models the different effects that different relations have on message propagation.
3. **Self-Loop Transform ($W_0^{(l)}$)**:
    
    - A separate weight matrix $W_0^{(l)}$ is used for the self-loop connection, allowing a node's own features to influence its updated embedding.
4. **Normalization Factor ($c_{v, r}$)**:
    
    - A normalization constant (e.g., based on the degree of vv under relation rr) to balance contributions from neighbors.
5. **Activation Function ($\sigma$)**:
    
    - A non-linear activation function, such as ReLU.

---

#### R-GCN Summary of Operations

For each node v in the graph:

1. **Message Passing**:
    - Aggregate messages from neighbors for each relation rr using Wr(l)W_r^{(l)}.
2. **Self-Loop Update**:
    - Add the transformed self-loop contribution W0(l)hv(l)W_0^{(l)} \mathbf{h}_v^{(l)}.
3. **Normalization**:
    - Normalize the aggregated messages to prevent exploding or vanishing values.
4. **Non-Linearity**:
    - Apply an activation function to compute the final embedding.

#### Key Characteristics of R-GCN

- **Relation-Specific Weight Matrices**:
    - Enables the model to learn distinct transformations for each relation type.
- **Self-Loop Connections**:
    - Ensures that nodes retain their own information at each layer.
- **Parameter Efficiency**:
    - R-GCN uses techniques like basis decomposition or block diagonal matrices to reduce the number of parameters when the number of relations (∣R∣|R|) is large.

#### Simplified Version for 1 Relation

If there is only one relation (or no differentiation between relations), the R-GCN simplifies to a standard GCN:

$$\mathbf{h}_v^{(l+1)} = \sigma \left( \sum_{u \in \mathcal{N}(v)} \frac{1}{c_{v}} W^{(l)} \mathbf{h}_u^{(l)} + W_0^{(l)} \mathbf{h}_v^{(l)} \right)$$

This shows that R-GCN generalizes GCNs to handle multi-relational data effectively.

#### Applications of R-GCN

- **Knowledge Graph Completion**:
    - Predict missing edges or node attributes in knowledge graphs with multi-relational edges.
- **Social Network Analysis**:
    - Capture different types of relationships in social networks (e.g., friendships, professional ties).
- **Recommender Systems**:
    - Handle diverse user-item interactions with relation-specific dynamics.

#### Challenges and Solutions

- **Parameter Explosion**:
    - When the number of relations |R| is large, the number of parameters grows linearly with |R|.
    - **Solution**: Use parameter sharing techniques like basis decomposition or block diagonalization.
- **Scalability**:
    - Large graphs with many nodes and edges can make message passing computationally expensive.
    - **Solution**: Employ sampling methods (e.g., GraphSAGE) to reduce computational overhead.

### Flexibility of GCN

the flexibility in graph neural networks allows for experimentation with various network architectures. Instead of sticking to Multi-Layer Perceptrons (MLPs) for each edge, you can explore different network types. For instance, you could replace an MLP with an LSTM or any other type of recurrent network architecture. Taking it further, you could even introduce convolutional neural networks (CNNs) into the mix. This would mean that one node's input could be an image, and the transformation during the edge operation would involve processing that image through the CNN.

The possibilities are wide open, and researchers often try out different approaches to see what works best for a given scenario. Additionally, the notion of shared weight matrices can also be explored in various ways. Instead of having shared weights all the way, you might experiment with multiple weight matrices, akin to having multiple filters in convolutional layers. The sharing of weights can extend not only between edges but also deeper into the network, allowing for reuse of weights at different levels. Advanced techniques, such as tying weights in specific ways, are also possible.

## Application: Query Embedding

Query embedding involves encoding complex queries over knowledge graphs into a vector space, facilitating efficient query processing and reasoning. This approach enables models to handle intricate query patterns beyond simple link prediction. Techniques in this domain often leverage GNNs to capture the structural and relational complexities inherent in queries.

#### Loss Functions in Graph Learning

In supervised graph learning tasks, models are trained to minimize a loss function that measures the discrepancy between the predicted outputs and the actual labels. For node classification, a common loss function is the cross-entropy loss:

L=−∑i∈YL∑c=1CYiclog⁡(Y^ic)\mathcal{L} = -\sum_{i \in \mathcal{Y}_L} \sum_{c=1}^C Y_{ic} \log(\hat{Y}_{ic})

where:

- YL\mathcal{Y}_L is the set of labeled nodes.
    
- CC is the number of classes.
    
- YicY_{ic} is a binary indicator (0 or 1) if node ii belongs to class cc.
    
- Y^ic\hat{Y}_{ic} is the predicted probability of node ii belonging to class cc.
    

Minimizing this loss encourages the model to produce accurate class probability distributions for the nodes.
