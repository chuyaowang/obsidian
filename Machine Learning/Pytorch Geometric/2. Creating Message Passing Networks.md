## General definition of the message passing neural network (MPNN)

$$
\mathbf{x}_i^{(k)} = \gamma^{(k)} \left( \mathbf{x}_i^{(k-1)}, \bigoplus_{j \in \mathcal{N}(i)} \, \phi^{(k)}\left(\mathbf{x}_i^{(k-1)}, \mathbf{x}_j^{(k-1)},\mathbf{e}_{j,i}\right) \right),
$$

The formula is the **general definition of a Message Passing Neural Network (MPNN)**. It describes how node features are updated at each layer by exchanging information with neighbors. This is the core abstraction behind all PyG GNN layers, including GCNConv, GraphSAGE, GAT, EdgeConv, and others.

Below is a structured explanation of every term and how they fit together.

---

### 🧩 What each symbol represents

#### Node feature at layer $k$: $\mathbf{x}_i^{(k)}$

This is the updated embedding of node $i$ after layer $k$.  
It is what the GNN learns: a vector representing the node’s meaning after aggregating information from neighbors.

#### Previous layer’s node feature: $\mathbf{x}_i^{(k-1)}$

This is the input to the current layer.  
At layer 0, $\mathbf{x}_i^{(0)}$ is the raw node feature vector from `data.x`.

---

### 🔗 Neighborhood: $\mathcal{N}(i)$

This is the set of neighbors of node $i$.  
For each neighbor $j$, the GNN will compute a **message** and send it to $i$.

---

### 💬 Message function: $\phi^{(k)}(\cdot)$

This function defines **what message node $j$ sends to node $i$**.  
It can depend on:

- the central node’s features $\mathbf{x}_i^{(k-1)}$
- the neighbor’s features $\mathbf{x}_j^{(k-1)}$
- the edge features $\mathbf{e}_{j,i}$ (optional)

In PyG, this is implemented in the `message()` method of a `MessagePassing` layer .

Examples:

- In **GCNConv**, the message is a normalized linear transform of $\mathbf{x}_j$.
- In **EdgeConv**, the message uses both $\mathbf{x}_i$ and $\mathbf{x}_j - \mathbf{x}_i$.

---

### 🧮 Aggregation: $\bigoplus$

This symbol means a **permutation-invariant aggregation** over all incoming messages.

Common choices:

- **sum**  
- **mean**  
- **max**

PyG lets you choose this via `aggr="add"`, `"mean"`, or `"max"` in the `MessagePassing` constructor .

Aggregation ensures that the GNN does not depend on the order of neighbors.

---

### 🔧 Update function: $\gamma^{(k)}(\cdot)$

This function combines:

- the node’s previous features $\mathbf{x}_i^{(k-1)}$
- the aggregated message from neighbors

It produces the new node embedding $\mathbf{x}_i^{(k)}$.

In PyG, this corresponds to the `update()` method .

Examples:

- In **GCNConv**, the update is simply adding a bias.
- In **GraphSAGE**, the update is an MLP.
- In **GAT**, the update includes attention-weighted sums.

---

### 🧠 Putting it all together: the message passing cycle

Each GNN layer performs:

1. **Message**: neighbors compute messages  
   $$
   m_{j \to i} = \phi^{(k)}(\mathbf{x}_i, \mathbf{x}_j, \mathbf{e}_{j,i})
   $$

2. **Aggregation**: node $i$ collects all messages  
   $$
   M_i = \bigoplus_{j \in \mathcal{N}(i)} m_{j \to i}
   $$

3. **Update**: node $i$ updates its embedding  
   $$
   \mathbf{x}_i^{(k)} = \gamma^{(k)}(\mathbf{x}_i^{(k-1)}, M_i)
   $$

This is exactly the process described in the documentation’s explanation of the `MessagePassing` base class .

---

### 🧭 Why this formula matters

This single equation unifies almost all GNN architectures.  
Different GNNs differ only in:

- how they define **messages** ($\phi$)
- how they **aggregate** them ($\bigoplus$)
- how they **update** node states ($\gamma$)

This is why PyG’s `MessagePassing` class only requires you to implement:

- `message()` → $\phi$
- `update()` → $\gamma$
- choose `aggr` → $\bigoplus$

Everything else is handled automatically.

## The MessagePassing base class

The *MessagePassing* base class is the core abstraction that PyTorch Geometric uses to implement all graph neural network layers. It formalizes the message‑passing equation shown above and provides a clean interface for defining **how messages are computed**, **how they are aggregated**, and **how node states are updated**. Everything else—neighbor indexing, message routing, batching, and propagation—is handled automatically by the framework.

---

### 🧩 Purpose of the MessagePassing class

MessagePassing is designed to let you implement any message‑passing GNN by defining only three things:

- **The message function** ϕ (implemented as `message()`)
- **The aggregation operator** ⊕ (configured via `aggr="add"`, `"mean"`, or `"max"`)
- **The update function** γ (implemented as `update()`)

The class handles:

- Expanding node features into per‑edge tensors (`x_i`, `x_j`)
- Iterating over edges in the correct direction
- Aggregating messages efficiently
- Supporting bipartite graphs, heterogeneous graphs, and batched graphs
- GPU‑optimized propagation

This lets you focus on the math of your layer instead of the plumbing.

---

### 🧱 Key methods and what they do

#### 1. `__init__(aggr="add", flow="source_to_target", node_dim=-2)`

This sets the global behavior of the layer.

- **aggr** — how messages are combined: `"add"`, `"mean"`, `"max"`
- **flow** — direction of message passing:
  - `"source_to_target"` means edges (j → i)
  - `"target_to_source"` reverses the direction
- **node_dim** — which dimension of input tensors corresponds to nodes

This configuration determines how `propagate()` interprets `edge_index`.

---

#### 2. `propagate(edge_index, size=None, **kwargs)`

This is the *entry point* for message passing.

When you call:

```python
self.propagate(edge_index, x=x, norm=norm)
```

PyG automatically performs:

1. **Message computation**  
   Calls `message(x_j, x_i, norm, ...)` for each edge.

2. **Aggregation**  
   Sums/averages/maxes messages per target node.

3. **Update**  
   Calls `update(aggr_out, x, ...)` to produce new node embeddings.

It also automatically:

- Lifts node-level tensors into edge-level tensors (`x_j`, `x_i`)
- Handles bipartite graphs when `size=(N, M)` is provided
- Works with batched graphs (block‑diagonal adjacency)

---

#### 3. `message(...)`

This defines **what message each neighbor j sends to node i**.

Arguments passed to `propagate()` become available here, and PyG automatically generates:

- `x_j` — features of source nodes for every edge
- `x_i` — features of target nodes for every edge
- They have the shape of $[\text{num\_edges},\text{num\_features}]$

For example, if the edge index is defined as

``` python
edge_index = [[0, 1, 1, 2],
              [1, 0, 2, 1]]

```

`x_i` and `x_j` are respectively:

``` python
x_i = x[edge_index[1]]
x_j = x[edge_index[0]]
```

where `x` is the node features matrix.

Example from GCNConv:  

```python
def message(self, x_j, norm):
    return norm.view(-1, 1) * x_j

```

Here, each neighbor’s feature is normalized and sent as a message.

---

#### 4. `aggregate(inputs, index, dim_size)`

You rarely override this because `aggr="add"` etc. handle it.  
It combines all messages for each node.

---

#### 5. `update(aggr_out, ...)`

This defines how the node updates its embedding after aggregation.

Example:

```python
def update(self, aggr_out):
    return aggr_out + self.bias
```

In many layers, this is where MLPs or residual connections are applied.
