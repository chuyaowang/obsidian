# Simple GCN using PyG

## A simple two layer GCN

``` python
import torch
import torch.nn.functional as F
from torch_geometric.nn import GCNConv

class GCN(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = GCNConv(dataset.num_node_features, 16)
        self.conv2 = GCNConv(16, dataset.num_classes)

    def forward(self, data):
        x, edge_index = data.x, data.edge_index

        x = self.conv1(x, edge_index)
        x = F.relu(x)
        x = F.dropout(x, training=self.training)
        x = self.conv2(x, edge_index)

        return F.log_softmax(x, dim=1)
```

This two‑layer GCN is the minimal example of a **message‑passing neural network**: each layer aggregates information from neighbors (via `GCNConv`), transforms it, applies a nonlinearity, and finally produces class probabilities for each node.

---

### 🧩 Main components of the model

#### 1. GCNConv layers

Each `GCNConv` performs the core graph convolution:

- It takes node features `x` and the graph structure `edge_index`.
- It aggregates neighbor features using the normalized adjacency matrix.
- It applies a learned linear transformation.

In your model:

- `conv1` maps **input features → 16 hidden features**.
- `conv2` maps **16 hidden features → num_classes**.

These layers implement the GCN update rule:

$$
H^{(l+1)} = \sigma(\tilde{A} H^{(l)} W^{(l)})
$$

where $\tilde{A}$ is the normalized adjacency matrix derived from `edge_index`.

---

#### 2. Nonlinear activation (ReLU)

After the first convolution:

```python
x = F.relu(x)
```

ReLU introduces nonlinearity so the model can learn more expressive patterns than a simple linear transformation.

---

#### 3. Dropout

```python
x = F.dropout(x, training=self.training)
```

Dropout randomly zeroes some activations during training to prevent overfitting.  
It is only applied when `model.train()` is active.

---

#### 4. Log‑softmax output

```python
return F.log_softmax(x, dim=1)
```

This converts the final node‑level logits into log‑probabilities over classes.  
It is used with `F.nll_loss` during training.

---

### 🔄 What happens during the forward pass

#### Step‑by‑step flow

1. **Input extraction**

   ```python
   x, edge_index = data.x, data.edge_index
   ```

   - `x`: node feature matrix $[N, F]$
   - `edge_index`: COO adjacency $[2, E]$ (as described in the [PyG docs](https://pytorch-geometric.readthedocs.io/en/latest/get_started/introduction.html))

2. **First graph convolution**

   ```python
   x = self.conv1(x, edge_index)
   ```

   - Aggregates neighbor features.
   - Applies a learned weight matrix.
   - Produces hidden features $[N, 16]$.

3. **ReLU activation**

   ```python
   x = F.relu(x)
   ```

4. **Dropout**

   ```python
   x = F.dropout(x, training=self.training)
   ```

5. **Second graph convolution**

   ```python
   x = self.conv2(x, edge_index)
   ```

   - Produces class logits $[N, \text{num\_classes}]$.

6. **Log‑softmax**

   ```python
   return F.log_softmax(x, dim=1)
   ```

---

### 🧠 What the network is learning

- **Node embeddings** after each GCN layer.
- How to combine a node’s own features with its neighbors’ features.
- Patterns in the graph structure that correlate with node labels.
- A mapping from hidden representations to class probabilities.

Because the graph is passed in as `data`, the model learns **on the graph structure itself**, not just on features.

---

### 🧭 Why this architecture works well for node classification

- The first GCN layer mixes information from 1‑hop neighbors.
- After ReLU and dropout, the second layer mixes information again, effectively capturing **2‑hop neighborhoods**.
- The final softmax gives a probability distribution for each node’s class.
.

## The GCN Conv Module

Message passing in `GCNConv` consists of a very specific sequence of operations: **normalize the adjacency**, **send messages from neighbors**, **aggregate them**, and **apply a learned linear transformation**.

---

### 🧠 What happens inside a GCNConv layer

A `GCNConv` layer implements the original Kipf & Welling GCN update rule:

$$
H^{(l+1)} = \sigma\left(\tilde{D}^{-1/2}\tilde{A}\tilde{D}^{-1/2} H^{(l)} W^{(l)}\right)
$$

Each part corresponds to a concrete operation in PyG:

- **$\tilde{A}$** is the adjacency matrix with self‑loops added.
- **$\tilde{D}$** is the degree matrix of $\tilde{A}$.
- **$W^{(l)}$** is the learnable weight matrix inside the layer.
- **$\sigma$** is the activation (ReLU in your model).

PyG implements this using its `MessagePassing` base class, where `GCNConv` defines:

- **message()** — what each neighbor sends  
- **aggregate()** — how messages are combined  
- **update()** — how the node updates its representation

---

### 🔄 Step‑by‑step: Message passing in the first GCN layer

#### 1. Input to the layer

You pass:

- `x`: node feature matrix $[N, F]$
- `edge_index`: COO adjacency $[2, E]$

#### 2. Add self‑loops

GCNConv automatically adds edges $i \to i$ so each node includes its own features in aggregation.

#### 3. Compute normalization coefficients

For each edge $i \to j$, GCNConv computes:

$$
\text{norm}_{ij} = \frac{1}{\sqrt{d_i d_j}}
$$

This is the symmetric normalization from the GCN paper.

#### 4. Linear transformation

Before aggregation, each node feature is transformed:

$$
x' = x W
$$

This is a standard dense layer applied to every node.

#### 5. Message passing

For each edge $i \to j$:

- Node $i$ sends the message  
  $$
  m_{i \to j} = \text{norm}_{ij} \cdot x'_i
  $$

This is implemented in `message()`.

#### 6. Aggregation

For each node $j$, all incoming messages are summed:

$$
h_j = \sum_{i \in \mathcal{N}(j)} m_{i \to j}
$$

This is the default `"add"` aggregation in GCNConv.

#### 7. Output of the first layer

You now have hidden features $[N, 16]$.  
Your model then applies:

- ReLU  
- Dropout  

These are **not** part of GCNConv itself.

---

### 🔁 Message passing in the second GCN layer

The second layer repeats the same process, but now:

- Input features are $[N, 16]$
- Output features are $[N, num_classes]$
- No activation is applied inside the layer
- You apply `log_softmax` afterward

The message‑passing steps are identical:

1. Add self‑loops  
2. Compute normalized adjacency  
3. Apply linear transform $W^{(2)}$  
4. Send normalized messages  
5. Aggregate by summation  
6. Produce logits for each node  

Because the second layer outputs class scores, you do not apply ReLU afterward.

---

### 🧩 How the two layers work together

- **Layer 1** mixes information from 1‑hop neighbors → produces expressive hidden embeddings.
- **Layer 2** mixes information again → each node now incorporates information from 2‑hop neighborhoods.
- The final softmax turns these into class probabilities.

This is exactly the architecture shown in the PyG documentation under the `GCN` model section.   [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/modules/nn.html)

## Training code explained

``` python
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = GCN().to(device)
data = dataset[0].to(device)
optimizer = torch.optim.Adam(model.parameters(), lr=0.01, weight_decay=5e-4)

model.train()
for epoch in range(200):
    optimizer.zero_grad()
    out = model(data)
    loss = F.nll_loss(out[data.train_mask], data.y[data.train_mask])
    loss.backward()
    optimizer.step()
```

The training loop is the standard way PyTorch Geometric trains a **node‑classification GCN** on the Cora dataset. Breaking it down step by step clarifies what each component does and why it’s needed.

---

### 🧩 Device selection and model setup

#### Choosing CPU or GPU

```python
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
```

This selects a GPU if available; otherwise it falls back to CPU. GNNs benefit from GPU acceleration because message passing involves large sparse operations.

#### Creating the model and moving it to the device

```python
model = GCN().to(device)
```

- Instantiates your two‑layer GCN.
- Moves all parameters (`conv1`, `conv2`, weight matrices) to the selected device.

#### Loading the graph and moving it to the device

```python
data = dataset[0].to(device)
```

For Cora, `dataset[0]` is a **single graph** containing:

- `data.x` — node features
- `data.edge_index` — graph connectivity in COO format
- `data.y` — node labels
- `data.train_mask`, `val_mask`, `test_mask` — boolean masks telling which nodes belong to which split  
    These masks are described on the page you’re viewing [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/get_started/introduction.html).

---

### ⚙️ Optimizer and hyperparameters

#### Adam optimizer

```python
optimizer = torch.optim.Adam(model.parameters(), lr=0.01, weight_decay=5e-4)
```

- **Learning rate (lr=0.01)** controls how big each parameter update is.
- **Weight decay (5e‑4)** is L2 regularization, which helps prevent overfitting by penalizing large weights.  
    This value is standard for GCNs on Cora.

Adam adapts the learning rate per parameter, making training stable even with sparse graph operations.

---

### 🔁 Training loop (200 epochs)

#### Setting the model to training mode

```python
model.train()
```

This activates dropout layers and ensures the model behaves in training mode.

#### Epoch loop

```python
for epoch in range(200):
```

GCNs on Cora typically converge well within 200 epochs.

---

### 🧠 Inside each training step

#### 1. Zero gradients

```python
optimizer.zero_grad()
```

Clears old gradients so they don’t accumulate.

#### 2. Forward pass

```python
out = model(data)
```

This runs:

- GCNConv layer 1 (message passing + linear transform)
- ReLU
- Dropout
- GCNConv layer 2
- Log‑softmax over classes

The output `out` has shape:

```
[num_nodes, num_classes]
```

#### 3. Compute loss on training nodes only

```python
loss = F.nll_loss(out[data.train_mask], data.y[data.train_mask])
```

This is crucial:

- `data.train_mask` selects only the labeled training nodes (140 nodes in Cora, as shown on the page) [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/get_started/introduction.html).
- `out[...]` are the predicted log‑probabilities.
- `data.y[...]` are the true labels.

`F.nll_loss` matches the `log_softmax` output of the model.

#### 4. Backpropagation

```python
loss.backward()
```

Computes gradients of the loss with respect to all model parameters.

#### 5. Parameter update

```python
optimizer.step()
```

Adam updates the weights using the computed gradients.

---

### 🎯 What the model is learning

Across epochs, the GCN learns:

- How to combine a node’s own features with its neighbors’ features.
- How to propagate information across the graph structure.
- How to map the resulting embeddings to the correct class labels.

Because only training nodes are used for the loss, the model must generalize across the graph to correctly classify validation and test nodes.

---

## Why no shuffling, no dataloader, and batching used

> In short, because the data contain one graph

- Unlike other types of data, a graph cannot be broken down into smaller pieces without disrupting learning.
- During training, the entire graph is used, but the loss is calculated only using the training nodes.
- Since there is only one graph, it is not shuffled, loaded, or batched.
	- For datasets like ENZYMES (600 graphs), a DataLoader is used to create **mini-batches** via block‑diagonal adjacency matrices
- These operations would be necessary if the data contain multiple graphs.
