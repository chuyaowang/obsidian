## GCN general form

$$
\mathbf{x}_i^{(k)} = \sum_{j \in \mathcal{N}(i) \cup \{ i \}} \frac{1}{\sqrt{\deg(i)} \cdot \sqrt{\deg(j)}} \cdot \left( \mathbf{W}^{\top} \cdot \mathbf{x}_j^{(k-1)} \right) + \mathbf{b},
$$

This equation describes the **GCN update rule**, and each term corresponds to a specific step in the GCNConv implementation. It describes how node $i$’s features are updated at layer $k$ by aggregating transformed and normalized features from its neighbors and itself.

---

### 🧩 Meaning of each term in the formula

$$
\mathbf{x}_i^{(k)} =
\sum_{j \in \mathcal{N}(i) \cup \{ i \}}
\frac{1}{\sqrt{\deg(i)} \cdot \sqrt{\deg(j)}} \cdot
\left( \mathbf{W}^{\top} \cdot \mathbf{x}_j^{(k-1)} \right)
+ \mathbf{b}
$$

#### 1. $\mathbf{x}_i^{(k)}$ — updated node features at layer $k$

This is the new embedding of node $i$ after the GCN layer has aggregated information from its neighbors.

#### 2. $\mathcal{N}(i) \cup \{i\}$ — neighbors plus self-loop

GCN adds self-loops so each node includes its own previous features in the update.  
This matches Step 1 in the implementation: *“Add self-loops to the adjacency matrix.”*

#### 3. $\mathbf{x}_j^{(k-1)}$ — previous-layer features of neighbor $j$

These are the features from the previous layer (or raw input features at layer 0).  
In code, this is the `x` passed into `forward()`.

#### 4. $\mathbf{W}^{\top}$ — learnable weight matrix

This is the linear transformation applied to node features before message passing.  
It corresponds to:

```python
x = self.lin(x)
```

in Step 2 of the implementation.

#### 5. Degree normalization: $\frac{1}{\sqrt{\deg(i)} \sqrt{\deg(j)}}$

This is the symmetric normalization used in GCNs.  
It ensures that:

- high-degree nodes don’t overwhelm low-degree nodes  
- the aggregation is numerically stable  
- the operator resembles the normalized Laplacian

In the implementation, this is computed as:

```python
deg_inv_sqrt[row] * deg_inv_sqrt[col]
```

where `row = i` and `col = j`.   [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/create_gnn.html)

#### 6. Summation over neighbors

$$
\sum_{j \in \mathcal{N}(i) \cup \{i\}}
$$

This is the aggregation step.  
GCN uses **sum aggregation**, which is why the layer inherits:

```python
super().__init__(aggr='add')
```

in the implementation.

#### 7. $\mathbf{b}$ — bias vector

After aggregation, a bias is added:

```python
out = out + self.bias
```

This is Step 6 in the implementation.

---

### 🔄 How this formula maps to the actual GCNConv code

The page breaks the formula into steps:  

1. Add self-loops  
2. Linear transform  
3. Compute normalization  
4. Normalize messages  
5. Aggregate  
6. Add bias  

The formula is simply the mathematical expression of these steps.

---

### 🧠 Intuition behind the formula

- Each neighbor $j$ sends a message to node $i$.  
- The message is the neighbor’s transformed feature vector, scaled by degree normalization.  
- Node $i$ sums all incoming messages (including its own).  
- A bias is added.  
- The result becomes the new node embedding.

This is the core idea of the GCN: **smooth features over the graph while applying a learned linear transformation**.

## Summary of operations

In this GCN implementation, the three components of the message‑passing equation correspond directly to three parts of the code on the page you’re viewing   [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/create_gnn.html):

- **Message function ϕ:** `message(self, x_j, norm)` multiplies each neighbor’s transformed feature `x_j` by the normalization coefficient `norm`.  
- **Aggregation function ⊕:** the layer uses `"add"` aggregation (sum), specified in `super().__init__(aggr='add')`, so all incoming messages to node *i* are summed.  
- **Update function γ:** the update step is simply adding the bias vector in `out = out + self.bias` after aggregation.

### The linear transformation is a node-level operation

It’s a great instinct to ask whether the **linear transformation** is the message function, because in many neural network layers the weight matrix is the core operation. But in the GCN implementation you’re looking at, the linear transformation is **not** the message function. It happens *before* message passing, and the message function is something more specific.

In this example, the linear transform is applied **once per node**, while the message function is applied **once per edge**.

---

#### 🧩 Why the linear transformation is *not* the message function

In the GCNConv implementation, the linear transformation:

```python
x = self.lin(x)
```

is applied **before** message passing begins. It transforms node features from dimension F to dimension F′. This is a node-level operation, not an edge-level one.

The message function, by contrast, is defined inside the `message()` method and is applied **per edge**, using lifted tensors `x_j` (source node features) and normalization coefficients.

---

#### 🧠 What the message function actually is in GCNConv

The message function is:

```python
def message(self, x_j, norm):
    return norm.view(-1, 1) * x_j
```

This corresponds exactly to the mathematical term:

$$
\frac{1}{\sqrt{\deg(i)}\sqrt{\deg(j)}} \cdot (W^\top x_j)
$$

The message function’s job is to:

- take the already-transformed feature of the **source node** (`x_j`)
- multiply it by the normalization coefficient (`norm`)
- produce the message sent along that edge

This is why the message function is *not* the linear transform itself. The linear transform produces `W x_j`, but the message function produces the **normalized** message that flows across edges.

---

#### 🧮 Summary of the three functions in GCNConv

- **Message function ϕ:**  
  `message(self, x_j, norm)` → computes normalized messages per edge.

- **Aggregation function ⊕:**  
  `"add"` (sum) → sums all incoming messages for each node.

- **Update function γ:**  
  `update(self, aggr_out)` → adds the bias term to the aggregated messages.

---

#### 🧭 Why this separation matters

GCNConv follows the general MPNN framework:

- Linear transform is a **node-wise preprocessing step**.
- Message function is an **edge-wise operation**.
- Aggregation is a **node-wise reduction**.
- Update is a **node-wise postprocessing step**.

This separation is what allows PyG to unify many different GNN architectures under the same `MessagePassing` interface.

## Appendix: the implementation code

``` python
import torch
from torch.nn import Linear, Parameter
from torch_geometric.nn import MessagePassing
from torch_geometric.utils import add_self_loops, degree

class GCNConv(MessagePassing):
    def __init__(self, in_channels, out_channels):
        super().__init__(aggr='add')  # "Add" aggregation (Step 5).
        self.lin = Linear(in_channels, out_channels, bias=False)
        self.bias = Parameter(torch.empty(out_channels))

        self.reset_parameters()

    def reset_parameters(self):
        self.lin.reset_parameters()
        self.bias.data.zero_()

    def forward(self, x, edge_index):
        # x has shape [N, in_channels]
        # edge_index has shape [2, E]

        # Step 1: Add self-loops to the adjacency matrix.
        edge_index, _ = add_self_loops(edge_index, num_nodes=x.size(0))

        # Step 2: Linearly transform node feature matrix.
        x = self.lin(x)

        # Step 3: Compute normalization.
        row, col = edge_index
        deg = degree(col, x.size(0), dtype=x.dtype)
        deg_inv_sqrt = deg.pow(-0.5)
        deg_inv_sqrt[deg_inv_sqrt == float('inf')] = 0
        norm = deg_inv_sqrt[row] * deg_inv_sqrt[col]

        # Step 4-5: Start propagating messages.
        out = self.propagate(edge_index, x=x, norm=norm)

        # Step 6: Apply a final bias vector.
        out = out + self.bias

        return out

    def message(self, x_j, norm):
        # x_j has shape [E, out_channels]

        # Step 4: Normalize node features.
        return norm.view(-1, 1) * x_j
```
