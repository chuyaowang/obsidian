# Difference between GCN and Edge Convolution

A [GCN](Machine%20Learning/Pytorch%20Geometric/2.1.%20Implementing%20a%20GCN%20Network.md) layer and an [Edge Convolution](Machine%20Learning/Pytorch%20Geometric/2.2.%20Implementing%20Edge%20Convolution.md) layer are both built on the same message‑passing framework, but they implement **fundamentally different assumptions about what information should flow across edges and how neighborhoods should be defined**. The page you’re viewing lays out both implementations side‑by‑side, which makes the contrast especially clear.   [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/create_gnn.html)

---

## How GCN and EdgeConv differ at a structural level

### 🧱 What each layer assumes about the graph
- **GCN** assumes a *fixed* graph whose edges already encode meaningful relationships. The graph structure is part of the data (e.g., citation networks, social networks).  
- **EdgeConv** assumes the graph is *constructed* from the data, typically using k‑nearest neighbors in coordinate or feature space. The graph is not fixed; it is rebuilt each layer.

This difference alone leads to very different behaviors.

---

## How the message functions differ

### 🔹 GCN message function  
GCN sends a **degree‑normalized linear transformation** of the neighbor’s features:

\[
m_{j\to i} = \frac{1}{\sqrt{\deg(i)\deg(j)}}\, W x_j
\]

In the code, this is:

```python
return norm.view(-1, 1) * x_j
```  
  [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/create_gnn.html)

GCN messages depend only on the neighbor’s transformed features and the graph’s degree structure. There is **no explicit use of relative geometry**.

### 🔹 EdgeConv message function  
EdgeConv sends a message built from **absolute and relative features**:

\[
m_{j\to i} = h_\Theta\big(x_i,\; x_j - x_i\big)
\]

In the code:

```python
tmp = torch.cat([x_i, x_j - x_i], dim=1)
return self.mlp(tmp)
```  
  [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/create_gnn.html)

This explicitly encodes **local geometric structure** (differences between points), which GCN does not.

---

## How the aggregation differs

### 🔹 GCN uses **sum** aggregation  
GCN smooths features over the graph by summing normalized messages. This produces a diffusion‑like effect.

### 🔹 EdgeConv uses **max** aggregation  
EdgeConv picks the strongest local geometric signal. This is analogous to max‑pooling in CNNs and makes it sensitive to edges, corners, and local shape.

---

## How the graph structure behaves

### 🔹 GCN: graph is fixed  
Edges come from the dataset and do not change across layers.

### 🔹 EdgeConv: graph is dynamic  
DynamicEdgeConv recomputes the k‑NN graph at every layer:

```python
edge_index = knn_graph(x, self.k, batch, ...)
```  
  [pytorch-geometric.readthedocs.io](https://pytorch-geometric.readthedocs.io/en/latest/tutorial/create_gnn.html)

As features evolve, neighborhoods change. This lets the model group points by learned similarity rather than raw coordinates.

---

## What each layer is best suited for

### 🟦 GCN is best for:
- Citation networks  
- Social networks  
- Knowledge graphs  
- Any domain where edges represent **semantic** relationships, not geometry

### 🟩 EdgeConv is best for:
- Point clouds  
- Meshes  
- 3D vision tasks  
- Any domain where **local geometry** matters and neighborhoods should adapt

---

## Summary table

| Aspect | GCN | EdgeConv |
|-------|------|-----------|
| Graph structure | Fixed | Dynamic (k‑NN recomputed each layer) |
| Message function | Linear transform + degree normalization | MLP over \([x_i, x_j - x_i]\) |
| Uses geometry? | No | Yes (relative differences) |
| Aggregation | Sum | Max |
| Effect | Smooths features | Detects local geometric patterns |
| Best for | Relational graphs | Point clouds, geometric data |
