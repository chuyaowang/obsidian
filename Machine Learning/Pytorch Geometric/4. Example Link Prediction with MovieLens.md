# Link Prediction with Movie Lens

## Network explained

The network in the article is a **heterogeneous link‑prediction GNN** built from three conceptual parts:  
(1) *learnable node feature encoders*,  
(2) *a two‑layer GraphSAGE message‑passing backbone converted to hetero form*, and  
(3) *a dot‑product edge classifier*.  
Each part has a clear input, output, and purpose in the link‑prediction pipeline.   [medium.com](https://medium.com/@pytorch_geometric/link-prediction-on-heterogeneous-graphs-with-pyg-6d5c29677c70)

---

### 🧩 Overall architecture at a glance
The model is:

```
User/Movie Embeddings → Heterogeneous SAGEConv layers → Node embeddings → Dot‑product classifier → Link prediction score
```

This structure is chosen because:

- users and movies have different feature spaces (heterogeneous graph)  
- link prediction requires node embeddings, not node labels  
- dot‑product scoring is a standard, efficient way to predict edges  
- GraphSAGE works well with neighbor sampling (LinkNeighborLoader)

---

### 🧱 1. Input feature layers (node encoders)

#### User encoder
```python
self.user_emb = nn.Embedding(num_users, hidden_channels)
```
**Input:** user node IDs  
**Output:** a learned embedding vector for each user  
**Rationale:** users have *no* features in MovieLens, so the model must learn them from scratch.

#### Movie encoder
```python
self.movie_lin = nn.Linear(20, hidden_channels)
self.movie_emb = nn.Embedding(num_movies, hidden_channels)
```
**Input:**  
- 20‑dimensional genre one‑hot vector  
- movie ID  

**Output:**  
A movie embedding = linear(genre) + learned embedding  

**Rationale:**  
Genres give semantic information, but shallow embeddings add flexibility and capacity.

---

### 🔁 2. Two‑layer GraphSAGE GNN (converted to heterogeneous)

#### Base GNN
```python
self.conv1 = SAGEConv(hidden, hidden)
self.conv2 = SAGEConv(hidden, hidden)
```

#### After `to_hetero(...)`
The model becomes a **type‑aware** GNN with separate parameters per edge type.  
**Input:**  
`x_dict` (user features, movie features) and `edge_index_dict` (rates, rev_rates)  

**Output:**  
Updated embeddings for each node type.

#### Rationale
- GraphSAGE supports neighbor sampling (required for large graphs).  
- Two layers allow information to propagate across multi‑hop neighborhoods.  
- `to_hetero` automatically creates separate SAGEConv modules for each relation type, which is essential because user→movie and movie→user edges have different semantics.   [medium.com](https://medium.com/@pytorch_geometric/link-prediction-on-heterogeneous-graphs-with-pyg-6d5c29677c70)

---

### 🔗 3. Edge‑level classifier (dot‑product)

```python
edge_feat_user = x_user[src]
edge_feat_movie = x_movie[dst]
return (edge_feat_user * edge_feat_movie).sum(-1)
```

**Input:**  
The embeddings of the two nodes forming each supervision edge.

**Output:**  
A scalar score per edge (before sigmoid).

**Rationale:**  
Dot‑product is a standard link‑prediction scoring function:  
- high score → embeddings aligned → likely edge  
- low score → embeddings orthogonal → unlikely edge  
It is simple, fast, and works well with SAGEConv.

---

### 🧠 Why this design works for heterogeneous link prediction

- **Heterogeneous structure:** Users and movies have different feature spaces and relations; `to_hetero` handles this cleanly.  
- **Learnable embeddings:** Users lack features; movies have sparse features. Embeddings compensate for this.  
- **GraphSAGE backbone:** Works with sampled subgraphs (LinkNeighborLoader), enabling scalability.  
- **Dot‑product classifier:** Efficient and well‑suited for binary link prediction.  
- **Separation of message‑passing edges vs. supervision edges:** Prevents leakage and ensures proper training.   [medium.com](https://medium.com/@pytorch_geometric/link-prediction-on-heterogeneous-graphs-with-pyg-6d5c29677c70)
