> Use the message passing base class to implement an edge convolution layer

## General form of edge convolution

$$
\mathbf{x}_i^{(k)} = \max_{j \in \mathcal{N}(i)} h_{\mathbf{\Theta}} \left( \mathbf{x}_i^{(k-1)}, \mathbf{x}_j^{(k-1)} - \mathbf{x}_i^{(k-1)} \right),
$$

This formula describes the **Edge Convolution (EdgeConv)** layer, and each term corresponds to a specific part of how the layer computes messages and updates node features. It expresses a *dynamic*, *local*, and *geometric* message‑passing rule.

---

### 🧩 Meaning of each term in the EdgeConv formula

#### 🔹 $\mathbf{x}_i^{(k)}$ — updated feature of node $i$ at layer $k$

This is the new embedding for node $i$ after the EdgeConv layer processes its neighborhood. It replaces the previous feature vector $\mathbf{x}_i^{(k-1)}$.

#### 🔹 $\mathcal{N}(i)$ — neighbors of node $i$

This is the set of nodes connected to $i$. EdgeConv computes a message for **each neighbor** $j$, then aggregates them.

#### 🔹 $\mathbf{x}_i^{(k-1)}$ and $\mathbf{x}_j^{(k-1)}$ — previous-layer node features

These are the input features at layer $k-1$.  

- $\mathbf{x}_i^{(k-1)}$: the *central* node’s features  
- $\mathbf{x}_j^{(k-1)}$: the *neighbor* node’s features  

In the PyG implementation, these appear as `x_i` and `x_j` inside the `message()` method. See [3. `message(...)`](Machine%20Learning/Pytorch%20Geometric/2.%20Creating%20Message%20Passing%20Networks.md#3.%20`message(...)`)

#### 🔹 $\mathbf{x}_j^{(k-1)} - \mathbf{x}_i^{(k-1)}$ — relative feature difference

This term captures **how neighbor $j$ differs from node $i$**.  
It is crucial because EdgeConv is designed for point clouds and geometric data, where *relative differences* encode local geometry.

In the code, this is computed as:

```python
tmp = torch.cat([x_i, x_j - x_i], dim=1)
```

#### 🔹 $h_{\mathbf{\Theta}}$ — a learnable MLP

This is a neural network (usually a small MLP) that processes the concatenated vector:

$$
\left[\mathbf{x}_i^{(k-1)} \,\|\, \mathbf{x}_j^{(k-1)} - \mathbf{x}_i^{(k-1)}\right]
$$

It learns how to combine absolute and relative features.  
In the implementation, it is:

```python
self.mlp = Seq(
    Linear(2 * in_channels, out_channels),
    ReLU(),
    Linear(out_channels, out_channels)
)
```

#### 🔹 $\max_{j \in \mathcal{N}(i)}$ — max aggregation over neighbors

EdgeConv uses **max pooling** to aggregate messages from neighbors.  
This makes the layer sensitive to the *most prominent local geometric feature*.

In the PyG class, this is set by:

```python
super().__init__(aggr="max")
```

---

### 🧠 Intuition behind the formula

EdgeConv computes, for each neighbor $j$:

- how different $j$ is from $i$  
- how to combine that difference with $i$’s own features  
- how to extract the strongest geometric signal via max pooling  

This makes EdgeConv particularly effective for point clouds, meshes, and dynamic graphs where local geometry matters.

---

## Summary of operations

The EdgeConv implementation in this example defines its three message‑passing components very cleanly. In the notation of the MessagePassing framework, they are:

- **Message function ϕ:** `message(self, x_i, x_j)` builds the per‑edge input by concatenating `[x_i, x_j − x_i]` and feeding it through the MLP. 
- **Aggregation function ⊕:** `"max"` aggregation, set in `super().__init__(aggr="max")`, takes the elementwise maximum over all neighbor messages.
- **Update function γ:** the default identity update—EdgeConv does not override `update()`, so the aggregated max‑pooled message becomes the new node feature.

---

## Why is it called edge convolution

Edge Convolution gets its name because the operation is defined **on edges rather than on nodes**, even though the graph may not come with edges originally. In EdgeConv, the “edge” is created dynamically between a point \(i\) and each of its neighbors \(j\), and the convolutional kernel is applied **to the feature pair \((x_i, x_j - x_i)\)** associated with that edge.

---

### 🔹 Where the “edge” comes from
Even if your data is just a point cloud (a set of points with no edges), EdgeConv **constructs edges** by building a *k‑nearest‑neighbor graph*:

- Each point \(i\) connects to its \(k\) nearest neighbors \(j\).
- These connections are treated as **edges**.
- The message function is applied **per edge**.

So the “edge” is not a physical edge in the dataset—it is a **learned or constructed relationship** between two points.

---

### 🔹 Why it’s called *Edge* Convolution
Because the convolutional operation is applied **on each edge**, not on each node:

\[
h_\Theta(x_i, x_j - x_i)
\]

This function is evaluated **for every edge \((j \to i)\)**.  
Then the results are aggregated (max-pooled) over all edges incoming to node \(i\).

This mirrors how CNNs apply filters over local neighborhoods in images—but here the neighborhood is defined by edges in a graph.

---

### 🔹 What makes the edge important
The edge defines:

- **which points interact** (via k‑NN)
- **the direction of message passing** (source \(j\) → target \(i\))
- **the geometric relationship** (captured by \(x_j - x_i\))

The term \(x_j - x_i\) is literally a **feature of the edge**, representing the relative displacement between two points.

---

### 🔹 Summary
- The “edge” in EdgeConv is the connection between a point and its neighbors.
- These edges are often **constructed dynamically** using k‑NN.
- The convolution is applied **on each edge**, using both absolute and relative features.
- The name reflects that the core computation happens **on edges**, not nodes.

---

## Dynamic edge convolution

Dynamic Edge Convolution builds directly on the EdgeConv layer, but adds one crucial behavior: **the graph is recomputed at every forward pass, and therefore every layer sees a different neighborhood structure**. 

---

### 🔄 What “dynamic” means in DynamicEdgeConv

A standard GNN layer uses a **fixed** `edge_index` that comes from the dataset. DynamicEdgeConv instead **rebuilds the graph from scratch** at each layer using k‑nearest neighbors in the current feature space:

```python
edge_index = knn_graph(x, self.k, batch, loop=False, flow=self.flow)
```

This means:

- At layer 0, neighbors are chosen based on raw input features (often coordinates).
- After the first EdgeConv layer transforms the features, the next layer recomputes neighbors based on the new embeddings.
- As features evolve, the graph structure evolves with them.

So **each layer can have a different set of edges**.

This is why the documentation emphasizes that EdgeConv is “a dynamic convolution, which recomputes the graph for each layer using nearest neighbors in the feature space.”

---

### 🧩 Why dynamic recomputation is useful

Dynamic graphs are especially powerful for point clouds and geometric data because:

- Local neighborhoods in raw coordinates may not reflect semantic structure.
- As features become more abstract, the model can group points by learned similarity rather than physical proximity.
- The graph adapts to the task, allowing the network to capture non‑rigid shapes, deformations, or complex manifolds.

This is one of the reasons EdgeConv is used in architectures like DGCNN (Dynamic Graph CNN).

---

### 🧠 How the implementation works

#### 1. Inherit from EdgeConv  

DynamicEdgeConv reuses the message and aggregation logic of EdgeConv:

```python
class DynamicEdgeConv(EdgeConv):
    ...
```

EdgeConv already defines:

- **message function**: MLP over `[x_i, x_j − x_i]`
- **aggregation**: max pooling
- **update**: identity

#### 2. Override `forward()` to rebuild the graph

```python
def forward(self, x, batch=None):
    edge_index = knn_graph(x, self.k, batch, loop=False, flow=self.flow)
    return super().forward(x, edge_index)
```

Key points:

- `knn_graph(x, k)` finds the k nearest neighbors **in feature space**, not coordinate space unless coordinates are the features.
- `batch` ensures k‑NN is computed separately for each graph in a mini‑batch.
- `flow=self.flow` ensures consistency with the message‑passing direction.

#### 3. Pass the new edges to EdgeConv  

`super().forward(x, edge_index)` runs the usual EdgeConv message passing on the newly built graph.

---

### 🧭 What changes from layer to layer?

Because `x` changes after each EdgeConv layer, the k‑NN graph changes too:

- Early layers: neighbors reflect geometric proximity.
- Later layers: neighbors reflect learned semantic similarity.
- The graph becomes more “task‑aware” as the network deepens.

This is fundamentally different from GCN, GraphSAGE, or GAT, which operate on a **fixed** graph.

---

### 🧪 Example of how edges evolve

Imagine a point cloud of a human figure:

- In early layers, points on the arm connect mostly to nearby arm points.
- After several layers, the model may learn that left and right arms share semantic structure, so their features become similar.
- k‑NN in feature space may then connect left‑arm points to right‑arm points, helping the model learn symmetry.

This dynamic behavior is exactly what makes EdgeConv powerful for shape classification and segmentation.

---

### 🧭 Closing thought

DynamicEdgeConv gives you a graph that **changes at every layer**, allowing the model to adaptively reshape neighborhoods based on learned features rather than fixed geometry. This is a major reason why it performs so well on point clouds and other geometric datasets.

If you’re planning to use DynamicEdgeConv, it would help to know whether your data has meaningful coordinates or whether you’re working with higher‑dimensional features.

## Appendix: code

``` python
import torch
from torch.nn import Sequential as Seq, Linear, ReLU
from torch_geometric.nn import MessagePassing

class EdgeConv(MessagePassing):
    def __init__(self, in_channels, out_channels):
        super().__init__(aggr='max') #  "Max" aggregation.
        self.mlp = Seq(Linear(2 * in_channels, out_channels),
                       ReLU(),
                       Linear(out_channels, out_channels))

    def forward(self, x, edge_index):
        # x has shape [N, in_channels]
        # edge_index has shape [2, E]

        return self.propagate(edge_index, x=x)

    def message(self, x_i, x_j):
        # x_i has shape [E, in_channels]
        # x_j has shape [E, in_channels]

        tmp = torch.cat([x_i, x_j - x_i], dim=1)  # tmp has shape [E, 2 * in_channels]
        return self.mlp(tmp)
```

``` python
from torch_geometric.nn import knn_graph

class DynamicEdgeConv(EdgeConv):
    def __init__(self, in_channels, out_channels, k=6):
        super().__init__(in_channels, out_channels)
        self.k = k

    def forward(self, x, batch=None):
        edge_index = knn_graph(x, self.k, batch, loop=False, flow=self.flow)
        return super().forward(x, edge_index)
```
